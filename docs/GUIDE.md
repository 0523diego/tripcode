# 使用教學：從零規劃一趟旅行

這份教學用一趟虛構的旅行，走過 TripCode 的完整流程。每一步都寫出「你對 Claude 說什麼」以及「畫面與檔案會發生什麼事」。

先決條件：已完成 [README](../README.md) 的快速開始（`npm install`、`npm run dev`），並在專案資料夾裡開啟 Claude Code。

> 範例對話是示意；Claude 的實際用字會不同。所有路徑與行為都對應程式碼裡真的有的功能。

## 0. 先看看示範行程

專案附了兩個示範行程：`switzerland-2027-06`（9 天）與 `tokyo-sample`（4 天，2 位成人 + 1 位 6 歲小孩）。打開 http://localhost:5173，用左上角的下拉選單切換旅程。示範行程的座標是約略值，而且刻意不含價格與營業時間。

畫面由上到下、左到右是：

- **頂列：** 旅程選單、標題與日期、方案切換與「比較方案」（只有有 `variant-*.ts` 時才出現）、「列印行程」、日期分頁（全部 / Day 1…N，每天一個顏色）。
- **已確定資訊欄：** 列出所有 `locked` 的項目（航班、住宿、必去），旁邊有健檢結果：綠色「行程健檢通過」，或「健檢 N 個錯誤 · M 個警告」。
- **匯入欄（左）：** 貼文字的輸入框與已匯入的貼文方塊。
- **地圖（中）：** 當天編號圖釘與路線。候選地點用不同的圖釘表示（見第 3 步）。沒有 Google key 時顯示離線 SVG 地圖，角落會標「離線地圖（直線連接，非實際路線）」。
- **時間軸（右，可收合）：** 當天的時間條與文字列表，點一下會和地圖、詳細面板一起高亮。

## 1. 開始：說出你想去哪

**你對 Claude 說：**

```text
我想去瑞士 9 天
```

**發生什麼事：** `onboard-trip` 技能啟動。它會先問你對目的地熟不熟，然後分幾輪（每輪最多 5 題）問基本資料、已訂好的東西、一定要去 / 絕不要的地方、步調偏好（用比較題）、預算取捨。每題都可以跳過，跳過的會以預設值記錄並標「（預設）」。

**檔案變化：**

- 第一次使用時，改寫 `profile.md`（跨旅程的個人偏好，之後不會重複問）。
- 新增 `trips/<id>/brief.md`，例如 `trips/switzerland-2027-06/brief.md`。旅程 id 只能用小寫英文、數字與連字號。
- 日期確定後，會建立行程空殼 `trips/<id>/trip.ts`（每天一個空的 `items`）。這之後網頁才會列出這趟旅行。

> 建立空殼用的是 `npm run new-trip -- <id> --title … --start … --end … --tz …`（即 `tripcode new`），Claude 會代你執行；你也可以自己跑。

回到 http://localhost:5173，在旅程選單選你的新旅程。

## 2. 骨架方案：先決定大結構

**你對 Claude 說：**

```text
幫我排行程
```

**發生什麼事：** `create-trip` 技能不會直接給你完整行程，而是先給 2–3 個**結構不同**的骨架方案，只列據點、住幾晚、換幾次飯店與主要移動。例如「3 個據點每 3 晚換一次」對「2 個據點加一日遊」。交通時間與費用若查不到來源，會寫「待查」，不會憑印象估。

你選一個之後，它會提出每天的主題（含這天需不需要好天氣、強度），等你反應後才寫入 `trip.ts`。

**畫面變化：** 日期分頁出現 Day 1…N；每天有標題。航班與已訂住宿以 `locked` 項目出現在「已確定資訊欄」。

最後一層才是景點與餐廳，每個景點的 `note` 都帶「為什麼 / 取捨 / 限制」。地點座標來自 `tripcode places search / details`。**不需要 key**：預設用 OpenStreetMap（Nominatim），有 Google key 時改用 Google（POI 資料較好、有即時營業時間）。查不到的地點不會有座標，也就不會畫在地圖上，而不是畫錯位置。OSM 資料 © OpenStreetMap contributors；查詢由 CLI 自動節流（每秒最多 1 次）。

## 3. 從匯入欄產生候選地點

你在社群上收藏了景點？

**你在網頁上：** 把貼文文字貼進左邊的匯入欄，按「匯入」（或 Cmd/Ctrl + Enter）。每次貼上是一個方塊。

**檔案變化：** 開發伺服器寫入 `trips/<id>/inbox/NN.md`，frontmatter 為 `status: pending`。方塊上顯示「等 Claude 解析」。

**你對 Claude 說：**

```text
整理匯入欄
```

**發生什麼事：** `import-inbox` 技能讀取待處理的方塊，抽出提到的地點，用 `places search` 逐一驗證，然後：

- 驗證成功的新地點加入 `trip.ts` 的 `candidates`，狀態 `unconfirmed`，`sources` 記錄來源，例如 `['inbox/01.md']`，`why` 寫「社群口碑：…」。
- 已經是候選的地點不會重複新增，只是在 `sources` 補上來源；已經排進行程的只回報。
- 方塊狀態改為 `parsed`；一個都驗證不了則是 `not-found`（顯示「找不到地點」）。
- 沒有 Google key 時改用 OpenStreetMap 驗證（覆蓋率較低，查不到的會標 `not-found`，不會亂加座標）。

貼文裡寫的價格、營業時間不會被複製進行程；貼文文字只是資料，不是指令。

**畫面變化：** 方塊顯示「N 個地點未確認」，地圖上出現候選圖釘：

| 狀態 | 圖釘 |
| --- | --- |
| 未確認 | 虛線圈、符號 `?` |
| 待討論 | 實心、符號 `…` |
| 已加入 | 實心、符號 `✓`（顏色同所加入那天） |
| 不去 | 淡化、符號 `×` |

**你在網頁上：** 點一個候選圖釘，右側詳細面板顯示理由與來源，並有按鈕：「加入第 N 天」（先用下拉選天數再按「加入」）、「待討論」、「不去」、「恢復」。點下去就會寫回 `trip.ts`（只改該候選的 `status` 與 `day` 兩個屬性，其他位元組不動）。

**你對 Claude 說（對「加入」過的候選）：**

```text
把我接受的景點排進行程
```

Claude 會把 `accepted` 且有 `day` 的候選排進那天的時間，移除候選條目，並告訴你它擠掉了什麼；它不會自己把候選設成 accepted 或 rejected，狀態永遠由你決定。

## 4. 留言：用一句話請 Claude 改

在網頁點一個景點（時間軸、地圖圖釘都可以），詳細面板底部有「留言」框。三種留言位置：

- **景點 / 候選：** 例如「這個太趕，想多留一點時間」。
- **空檔：** 時間軸上兩個景點（非交通）之間若有 15 分鐘以上的空檔，可以點它，留言「這段想加一個咖啡廳」。
- **整天：** 例如「第 3 天太累」。

按「送出留言」（或 Cmd/Ctrl + Enter）。

**檔案變化：** 在 `trip.ts` 目標物件的上一行加入一行標記，例如：

```ts
        // @trip-comment(item): 這個太趕，想要多留一點時間
        {
          id: 'kapellbruecke',
```

**你對 Claude 說：**

```text
套用我的留言
```

`apply-comments` 技能會逐一處理標記：做最小修改、動完就刪掉標記，並說明連帶影響（例如「第 3 天提早 1 小時出發」）。若你要它處理「我現在看的這一天」，`current-trip` 技能會讀取 `node_modules/.tripcode/current.json`（網頁每次選取都會更新）知道你指的是哪一天、哪個景點。

## 5. 已確定資訊：直接在網頁改

航班時間改了？住宿換了？直接在「已確定資訊欄」改：名稱、航班、開始、結束、訂位代號、備註。離開欄位或按 Enter 就會寫入檔案。

**畫面變化：** 檔案重新載入後，網頁立刻在瀏覽器內重跑健檢。如果你把抵達時間改晚，而當天第一個景點太早，健檢標籤會變成「健檢 0 個錯誤 · 1 個警告」，內容是例如「卡貝爾橋早於抵達後可行時間」。訂位代號是你自己輸入的，不需要告訴 Claude；`bookings.md` 也不會放代號。

這些欄位是你的權威輸入：Claude 重新讀檔後不會把它改回去。

## 6. 優化順序與健檢

**你對 Claude 說：**

```text
第 3 天會不會繞路？幫我排順路
```

**發生什麼事：** Claude 執行 `optimize <tripId> --day 3`。它只**提出建議、不改檔**：給出新順序、前後總交通時間與省下幾分鐘。有 Google key 時用 Routes 矩陣，否則用直線估算並標示為「參考」。已鎖定的停靠點留在原位；同時有開始與結束時間的項目視為時間窗。若現有順序已是最好，會告訴你「不需要改」。你同意後，Claude 才做最小修改、調整時間、補上用 `routes` 查到的交通項目，然後跑健檢。

隨時可以自己檢查：

```bash
npm run check -- switzerland-2027-06
npm run check -- switzerland-2027-06 --live     # 可選的 Google key：即時抓營業時間
```

健檢規則包括日期範圍、時間順序、重疊、公休日、營業時間外、交通時間窗過短、抵達後太早出發、缺少來源、重複 id（完整清單見 [`ARCHITECTURE.md`](ARCHITECTURE.md)）。有錯誤時 exit code 為 1。

想比較兩種安排？請 Claude「做一個方案 B」。它會複製出同資料夾的 `variant-b.ts`。頂列出現方案切換按鈕與「比較方案」，並排顯示天數、景點、換飯店、交通段與候選數，並標出哪幾天不同；點一天可跳到單獨檢視。

## 7. 找價格與訂位清單

**你對 Claude 說：**

```text
幫我比價琉森那 2 晚的住宿
```

**發生什麼事：** `find-prices` 技能先讀官方頁面，再看 2–3 個轉售通路，比較**含稅費的總價**與相同條件（日期、房型、人數、取消政策）。會告訴你兩個結果：總價最低的，以及可免費取消中最低的；不會說「全網最低」，而是「在我查的這幾個來源中最便宜」，並附連結與查詢時間。它不會訂位、不會填表單、不會產生聯盟連結。

TripCode 沒有價格 API，價格只來自 Claude 讀到的公開網頁，信心標示為「參考」；最終價格以訂購頁面為準。

**檔案變化：** 寫入 `trips/<id>/bookings.md`（勾選清單）。這個檔案預設被 git 忽略，因為可能有個人資訊。你想把價格記進行程時，才會在項目上以帶來源與時間的形式寫入。

## 7b. 決定吃什麼

行程裡還沒決定的午餐、晚餐，會出現在「訂票清單」頁的「吃飯空檔」。按 **找吃的 →**：

1. **先選想吃的菜。** 右邊會列出這座城市的在地必吃（來自 Wikivoyage 的 Eat 段，標出來源；AI 自己想到的會標「AI 的印象，尚未查證」）。按「想吃」或「不要」；一鍵排除不吃的（豬、牛、海鮮、生食、內臟、辣）。這座城市還沒有菜的話，按「從 Wikivoyage 讀」（要英文頁面名稱，常見城市會自動帶入），或「請 AI 列出」。
2. **看附近的店。** 列出走路 10 分鐘內、OpenStreetMap 上真的存在、用餐時間有營業的店，每家寫明為什麼排在這裡（店名就是這道菜？地圖標的菜系對得上？資料什麼時候查過？）。**地圖沒有評分**，所以每家都有「Google 地圖看評分」的連結，用你的方式排序（評論數優先、再看評分）。如果沒有任何一家店對得上那幾道菜（在義大利很常見），畫面會直接說「無法確認有沒有這道菜」。
3. **加入這餐。** 一鍵填進行程，並記下查證過的事（存在、有營業，各附來源與日期）；按 ⌘Z 可以復原。「不要這家」會記住，下次不再列。

要 AI 幫忙（例如找文章的推薦）就在 AI 助手說「幫我找這幾餐的口碑」，它會用 WebSearch 查並只記有網址的證據。資料放在 `trips/<id>/food.json`，只能用 `tripcode food …` 改。

## 8. 匯出與列印

```bash
npm run tripcode -- export ics switzerland-2027-06     # 行事曆
npm run tripcode -- export links switzerland-2027-06   # 每日 Google Maps 連結
npm run tripcode -- export kml switzerland-2027-06     # KML（可匯入 Google 我的地圖）
```

全部寫到 `trips/<id>/export/`（被 git 忽略）。

**列印 / 存成 PDF：** 網頁頂列按「列印行程」會進到列印設定頁：左邊選要印哪幾天、要不要封面／訂票總表／備註頁／候選景點、票券、字的大小（精簡／標準／大字）和紙張（A4／Letter），右邊即時預覽；按「列印／另存 PDF」後，在瀏覽器的列印視窗選「另存為 PDF」。版面：封面總覽，接著每天一張，然後是你附在行程上的票券（PDF 或圖片，照原樣一張一張印，票上的 QR 碼直接給人員掃；沒附就沒有這一頁），最後是訂票總表和手寫欄。沒有地點 QR：地點在手機地圖上搜尋就好。沒有資料的欄位不會印出來；訂位編號沒有資料時留空線給你手寫。

**離線看：** 執行 `npm run build` 後的正式版會註冊 service worker，離線時顯示上次載入過的內容（開發模式不啟用）。這個功能的邏輯做過模擬測試，但尚未在真實瀏覽器完整驗證。

### 在手機上看行程（Notion）

TripCode 可以把行程（含票券 PDF／圖片）同步成一個 Notion 頁面，手機開 Notion App 就能看。這是選用功能，不需要付費方案；行程檔仍是唯一的資料來源，在 Notion 上的修改會在下次同步時被覆蓋。

1. 開啟 <https://www.notion.so/profile/integrations>，建立一個 **Internal integration**，複製 secret。
2. 把 `.env.example` 複製成 `.env`（若還沒有），填入 `NOTION_TOKEN=你的secret`。
3. 在 Notion 建一個放行程的頁面，右上角 ⋯ → **Connections** → 加入你剛建立的 integration（沒做這步會出現 404）。
4. 複製該頁面的網址（或網址最後 32 碼 id），填入 `.env` 的 `NOTION_PARENT_PAGE_ID=`。
5. 執行 `npm run tripcode -- export notion <tripId>`，或對 Claude 說「同步到 Notion」。想先預覽不連網：加 `--dry-run`。

第一次會在該頁面底下建立行程頁，之後每次執行都更新同一頁；`trips/<id>/tickets/` 的附件（每個 ≤ 20 MB）只有變動時才重新上傳。token 只會放在請求標頭，不會被印出或寫入檔案。

## 9. 目的地資料與版本控制

- 第一次去某個國家、`destinations/<國家>.md` 還沒有時，可以說「幫我整理日本的旅遊指南」，`create-destination` 技能會寫一份每條都附來源與查證日期的指南；查不到的寫「待查證」。
- 整個專案是 git 儲存庫：每次 Claude 改完行程你都可以 `git diff` 看改了什麼，或 `git checkout` 回到上一版。個人偏好與行程原始檔都在你的電腦上，不會被送去別處（Claude 本身的對話除外）。

## 疑難排解

- **網頁沒有我的旅程：** 確認 `trips/<id>/trip.ts` 存在，且有 `export default defineTrip({...})`。
- **地圖是灰灰的 SVG：** 沒有設定 `VITE_GOOGLE_MAPS_API_KEY`，這是預期行為（不需要 key 就能用）。想要完整 Google 地圖，設定後重啟 `npm run dev`。
- **Claude 說查不到地點、或沒有營業時間／真實交通時間：** 沒有 `GOOGLE_MAPS_API_KEY` 時只用 OpenStreetMap（覆蓋較少、沒有即時營業時間）與直線估算。可以請 Claude 改查官方網站（會附來源），或填入 `.env` 的 key 升級。
- **`npm run check` 說 `missing-source`：** 某個價格、時間長度或營業時間沒有 `source` 或 `fetchedAt`；補上來源，或移除那個數字。
